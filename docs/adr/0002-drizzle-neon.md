# ADR-0002: Drizzle ORM + Neon Postgres

- Status: accepted
- Date: 2026-10-23

## Decision

- PostgreSQL. Production is Neon via the Vercel Marketplace; each preview deployment gets its own
  Neon branch. Local development uses Docker Postgres (`docker-compose.yml`).
- Drizzle ORM. The schema lives in `src/db/schema/`, one file per module. SQL migrations are
  generated by `drizzle-kit` into `drizzle/` and committed.
- The runtime uses the pooled URL (`DATABASE_URL`, `pg` Pool). Migrations use the direct URL
  (`DATABASE_URL_UNPOOLED`), because the pooler can break DDL inside transactions.
- Integration tests run on PGlite (Postgres compiled to WASM) with the real migrations, so CI
  needs no database for them. The e2e job uses a Postgres 17 service container.

## Faithfulness to `docs/schema.sql`

All 34 tables, 16 enums, the three check constraints (`orders_ref_format`,
`orders_org_when_biz`, `order_sizes_qty_pos`) and every index are reproduced. Deliberate additions,
each commented in the schema files:

| Change                                                                                    | Why                                                         |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Money columns are `numeric(12,2)` (ERD: plain `numeric`)                                  | Brief A5                                                    |
| `staff_users`: `email` NOT NULL, plus `email_verified`, `phone_verified`, `image`, `updated_at` | Better Auth user model (ADR-0003)                           |
| `staff_sessions`: `token`, `expires_at`, `ip_address`, `user_agent`                       | Better Auth session model (ADR-0003)                        |
| New tables `staff_accounts`, `auth_verifications`, `staff_two_factors`                    | Password hashes, auth verification values, TOTP secrets     |
| `messages`: `attempts`, `next_attempt_at`, `last_error` + index                           | Outbox bookkeeping (ADR-0004)                               |
| `orders.internal_note`                                                                    | B7 "internal note (never shown to the customer)"            |

## Consequences

- `pnpm db:generate` must run after every schema change. CI fails if the schema and the
  committed migrations drift.
- The Neon project currently lives in `us-east-2`. The brief targets `fra1`, so the production
  database should be created in Frankfurt (Neon `aws-eu-central-1`).
